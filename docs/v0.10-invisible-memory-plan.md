# v0.10 plan: almost-invisible memory

The product requirement is that Regurgitate improves an agent's decisions
without becoming another workflow the agent or user must manage. A missed
memory is cheaper than irrelevant context, a polluted corpus, or a blocked
primary task.

## Invariants

- Recall is selective, bounded, read-only, and safe to skip.
- Recording is rarer than recall and admits at most one novel lesson from a
  meaningful verified milestone or rejected approach.
- Agent-facing commands emit compact, stable, machine-readable results.
- Regurgitate never stores prompts, source, commands, paths, URLs, repository
  revisions, tool output, or environment values.
- Credential or history failure never becomes plaintext fallback.
- The CLI and one thin skill remain the integration surface; no MCP server or
  agent messaging subsystem is added.

## A. Selective, low-noise policy

- [ ] Rewrite the bundled skill to recall only when prior experience could
  materially change non-trivial work.
- [ ] Explicitly skip mechanical edits, simple questions, formatting, and
  tasks that already received an injected brief.
- [ ] Record at most one capsule, and only when it is novel, reusable,
  specific, and evidence-backed.
- [ ] Treat recall and recording failure as non-blocking.
- [ ] Keep the skill below 3,000 bytes and avoid routine user-facing chatter.

## B. Inferred controlled context

- [ ] Default `--project` to the current directory for direct recall and
  recording.
- [ ] Infer ecosystem, primary tool family, and source/config/docs artifact
  defaults from a bounded allowlist of project markers.
- [ ] Infer controlled risk shapes from ephemeral query text when explicit
  risk flags are absent.
- [ ] Preserve precedence: explicit flags, then task-query hints, then project
  defaults.
- [ ] Never inspect source contents, invoke project tools, or retain detected
  paths and marker names.

## C. Compact, non-blocking recall

- [ ] Add stable `matches`, `no_matches`, and `unavailable` recall statuses.
- [ ] Add an explicit best-effort mode that reduces credential/database
  failures to `unavailable` without hiding invalid CLI input.
- [ ] Use compact JSON for agent-facing recall and experience mutations.
- [ ] Keep no-match and unavailable results minimal and within the same public
  schema.

## D. Strict admission and deduplication

- [ ] Reject structurally valid but non-specific situations and lessons.
- [ ] Return field-specific, controlled JSON rejection reasons rather than an
  agent rewrite-provoking diagnostic.
- [ ] Treat an equivalent same-outcome report from the same conservative
  day/environment cohort as `duplicate` without mutating evidence.
- [ ] Preserve contradiction handling and independent later confirmations.

## E. Usefulness feedback and diagnostics

- [ ] Keep authenticated `experience confirm` as the only agent feedback path
  for an applied recalled lesson.
- [ ] Add a read-only aggregate metrics projection for capsule lifecycle,
  authenticated confirmations, and outcomes; expose no lesson text or IDs.
- [ ] Document that recall hit-rate and latency belong in the explicit paired
  benchmark, not silent recall-time telemetry.
- [ ] Keep backend detail in `status` and errors, never in ordinary recall
  output.

## F. Verification and release contract

- [ ] Add CLI, inference, admission, deduplication, privacy, and compatibility
  tests for every new behavior.
- [ ] Update the README, architecture, roadmap, and packaged skill contract.
- [ ] Run formatting, clippy with warnings denied, all targets, privacy tests,
  and `git diff --check`.
- [ ] Split implementation into reviewable commits by module.

## Operational acceptance targets

- A normal no-match recall emits one compact JSON object and exits
  successfully.
- Best-effort recall never blocks the primary task on unavailable encrypted
  state.
- Default recall remains at or below 300 approximate tokens.
- One task causes no more than one proactive recall and one novel capsule.
- Duplicate same-cohort recording does not increase raw or effective evidence.
- Any metadata inferred by Regurgitate is controlled, ephemeral, and visible
  only through its effect on ranking or the resulting capsule.
